Instalar el SDK oficial

Astro, Storyblok y Netlify · Home V2 · noviembre de 2026

Esta guía reemplaza los pasos de conexión del PDF 02 anterior. Si otra guía pide migrar la Story al tipo dedicado, no sigas ese paso: la conexión actual admite el bloque anidado en Default Page.

1. Instalá los dos paquetes

En el repositorio de Cabrales: usá Node.js 24.14 o superior y ejecutá npm ci. Ambos paquetes ya están declarados en package.json y en el archivo de versiones bloqueadas.

Si partís de otro proyecto Astro nuevo: agregá los dos paquetes que usa esta guía.

npm install @storyblok/astro@11 @storyblok/api-client@0.14.0
PaqueteQué hace
@storyblok/astro 11Atributos editables y StoryblokPreview. No trae el cliente de lectura ni requiere storyblok() en astro.config.mjs.
@storyblok/api-clientLee Delivery API desde el servidor con createApiClient() y client.stories.get().

2. Usá la estructura que ya existe

En Content → cabrales-home-v2 → Body, seleccioná el bloque cuya clave técnica sea cabrales-home-v2. Las escenas y los productos se editan dentro de ese bloque. No crees otra Story, no cambies el slug y no modifiques el tipo compartido.

Instalar no alcanza.

El SDK no configura tus credenciales. Cabrales ya lo llama desde src/lib/storyblok.ts. El transporte de src/lib/storyblok-delivery.ts valida el 301 de la CDN; src/lib/content.ts conserva el mapeo y los respaldos.

Conectar en local

Verificá los dos tokens antes de llevarlos a Netlify.

3. Completá el entorno local

En el Space actual → Settings → Access Tokens, identificá un token Public y otro Preview de Delivery API. Tomá el ID numérico del Space (no el de la Story).

# PowerShell: no sobrescribe un .env existente
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
VariableValor
STORYBLOK_REGIONeu · api.storyblok.com
STORYBLOK_PUBLIC_TOKENToken Public del Space. Solo contenido publicado.
STORYBLOK_PREVIEW_TOKENToken Preview del mismo Space. Permite leer borradores.
STORYBLOK_SPACE_IDID numérico del mismo Space. Sirve para comprobar la conexión y validar la firma del Visual Editor.

No subas el .env a Git ni pegues tokens en el frontend, capturas o chats. No necesitás un token de Management: esta conexión solo lee datos.

4. Probá borrador y publicado por separado

npm run cms:check
npm run cms:check -- --publicado

Esperá «Conexión OK» para draft y published, región eu y bloque en Body. Si cargaste el ID del Space, el comando lo contrasta con el de la API. El primer comando usa Preview; el segundo exige Public.

5. Abrí el Visual Editor, si lo necesitás

Ejecutá npm run dev:editor. Abrí https://localhost:4321/cabrales-home-v2/ y confirmá el certificado local. En Storyblok, agregá https://localhost:4321/ como entorno adicional si hace falta. Elegilo en la Story; no reemplaces el del sitio anterior.

Configurar Netlify

Las variables de tu PC no se copian automáticamente a producción.

6. Cargá las variables en el sitio correcto

Abrí cabrales-home → Project configuration → Environment variables. Revisá el contexto Production y, si el plan permite seleccionar el alcance, incluí Functions. Solo Builds no alcanza.

VariableQué se carga
STORYBLOK_PUBLIC_TOKENToken Public del Space actual. Obligatorio para leer la versión pública.
STORYBLOK_REGIONeu.
STORYBLOK_PREVIEW_TOKEN
STORYBLOK_SPACE_ID		Del mismo Space. Cargalos en el contexto que usás para el Visual Editor. No reemplazan al Public.
SITE_URL
SITE_INDEXABLE		Conservá la configuración de SEO. No habilites indexación como parte de la prueba.

7. Desplegá el código o aplicá las variables nuevas

  1. En Deploys, comprobá que el deploy publicado venga de main e incluya el cambio del SDK.
  2. Si cambiaste variables después de ese deploy, desplegá una vez más para que las funciones las reciban.
  3. Abrí cabrales-home.netlify.app/ y compará titular y descripción con la versión publicada de la Story.
  4. Para el Visual Editor remoto, usá la URL HTTPS del entorno como opción adicional y comprobá que se muestra el borrador.
Desplegar código no es publicar contenido.

Desplegá al cambiar código o variables. Para cambiar texto, imágenes o enlaces ya conectados, publicá la Story sin volver a desplegar.

Publicar y verificar

Probá la edición completa sin tocar el diseño ni reconstruir el sitio.

8. Probá una publicación editorial

  1. En Content → cabrales-home-v2 → Body → Cabrales Home V2 → Scenes → Café, guardá un cambio autorizado en title o description. Guardar no lo hace público.
  2. Revisalo en la vista previa. Cuando esté aprobado, hacé clic en Publish en la misma Story.
  3. Dejá vencer la caché pública de Netlify (60 segundos), más la propagación de Storyblok. Volvé a abrir la home y /cabrales-home-v2/. Verificá los valores nuevos sin otro deploy. Un TTL configurado en el Public de Storyblok puede sumar demora.
